# OV-JP8000 日志

> 用 OV-303 的硬件 (Pico 2 / ADS8688 / PCM5102 / ST7789 / AD5664) 做一台 JP-8000 风格合成器。
> 不是 303。硬件不变，只换固件/旋钮映射。

## 2026-10-19 立项

### 1) 目标
- 8 声部 SuperSaw VCO（7 锯齿、detune、mix、随机相位、立体声）
- JP-8000 风格 VCF：LP/BP/HP，12/24 dB，共振
- 单个 ADSR，用 SW1 切换目标 AMP / FILTER
- 旋钮：COLOR=Mix，DIST=Detune；其余 6 个中 4 个 ADSR，2 个 Cutoff/Resonance
- 开关：SW1=ADSR 目标，SW2=12/24dB，SW3=LP→BP→HP
- 不沿用 303 的 VCF/包络/音序器/PC 编辑器

### 2) 资料
- `参考资料\Roland-JP-8000-Service-Notes.pdf`（synthxl 下载）
- JP-8000：8 声部虚拟模拟；VCF 12/24 dB LP/BP/HP；两个 ADSR；SuperSaw 键跟踪 HPF。
- SuperSaw 参数参考 Adam Szabo《How to Emulate the Super Saw》与本机 `JP8000\pico_poly_vco`。

### 3) 新固件
- 目录：`pico_jp8000\pico_jp8000.ino`
- 表：2048 点带限 mipmap 锯齿（119 档），线性插值。
- VCF：TPT SVF，12 dB 一级；24 dB 两级（第一级共振，第二级温和）。
- ADSR：每声部独立；AMP 目标时直接控 VCA，FILTER 目标时 VCA 用固定 2ms/20ms 快速 gate，滤波器 +4 oct 固定深度。
- 立体声：7 锯齿按 detune 左右 pan；每声部 L/R 各一套 SVF；`i2s.write16(L,R)`。
- CV/Gate：AD5664 输出最高音 CV、Gate、滤波包络、AMP 包络。
- 屏幕：本版未驱动（背光关），参数用旋钮/串口。

  - **setup 第一行检查 SW3：开机按住前面板按键 -> 直接 BOOTSEL**
  - USB 3s 未挂载 -> 自动 `reset_usb_boot`
- 当前需要先让板子进 BOOTSEL 才能烧 v02 或退回 OV-03。

### 5) 恢复

- v02_safe（300MHz + 开机 SW3 进 BOOTSEL）成功烧入并枚举 COM21。
- v03：加 `p0/p1`（串口接管旋钮）和 `Q` CPU 统计。

- v09（当前）：**300MHz + 6 声部**（8 声部在 300MHz 下 core1 会到 100%，6 声部约 80%），去掉开机 SW3 立即检查（避免按住 SW3 时反复进 BOOTSEL），保留串口 `b` 命令。

### 7) 当前可运行状态（v09）
- 固件：`pico_jp8000_20261019_v09_6voice.uf2`
- 300MHz@1.20V，COM21 文本口，USB MIDI `OV-JP8000 MIDI`
- 6 声部 SuperSaw + TPT SVF (LP/BP/HP, 12/24dB) + 每声部 ADSR
- 实测 6 音和弦：RMS≈-21dBFS，peak≈-6dB，L/R corr≈0.64（立体声有效），centroid≈1.38kHz，>5kHz≈3.3%
- 6 声部 CPU：core1 约 80%（短测），释放尾音约 78%，空闲 4.4%
- 旋钮（物理丝印是 303 的，实际功能）：
  - TUNE=Attack, CUTOFF=Decay, RES=Sustain, ENV.MOD=Release
  - DECAY=Cutoff, ACCENT=Resonance, DIST=Detune, COLOR=Mix
- 开关：SW1=ADSR 目标 (AMP/FILTER)，SW2=12/24dB，SW3=LP→BP→HP
- 屏幕本版未驱动；参数用旋钮/串口 (`?` 查看命令)

### 8) v10/v11：独立 AMP/FILTER ADSR + 新旋钮映射 + Spire 式包络
- **ADSR**：
  - AMP 和 FILTER 各自保存一套 D/S/R；SW1 只切换"当前编辑哪一套"，两套包络同时工作（AMP→VCA，FILTER→Cutoff）。
  - 切换目标时，旋钮用 pickup 逻辑：不动旋钮就不覆盖另一套；动过才接上。
  - Attack 固定 1ms（删除 Attack 旋钮/命令）。
  - D/R 改为"实际段落时长"的指数：`coef=exp(-4.605/(T*SR))`，到 ~1% 的时间=T；不再用一阶时间常数（之前感觉 ADSR 很怪）。
  - 修复 AMP 包络被乘两次的问题：VCO 全幅进 VCF，AMP 包络只在 VCA 后乘。
- **新旋钮映射**：
  - TUNE=Cutoff，CUTOFF=Resonance
  - RES=D，ENV.MOD=S，DECAY=R（编辑当前目标）
  - ACCENT=Filter Env Depth（0..6 oct）
  - DIST=Detune，COLOR=Mix
- **开关**：SW1=编辑 AMP/FILTER ADSR；SW2=12/24dB；SW3=LP→BP→HP。
- **v12 测试 375MHz@1.40V + 8 声部**：USB 仍然枚举失败（1.40V 也没救回来），确认不是单纯电压问题；已恢复 v11。375 这版不可用。
- **当前（v11）**：300MHz@1.20V，6 声部，COM21 正常；空闲 core1≈4.4%。
- **采样率**：仍 48k。96k 在 6 声部下 CPU 不够；当前问题主要是滤波器/包络，不是 48k 本身。
- 产物：`pico_jp8000_20261019_v11.uf2`；`pico_jp8000_v11.ino.bak`（源码快照）。

### 9) v14/v15：全浮点 VCO + ADSR 范围 0.5ms..20s + 滤波系数每 16 采样更新
- **v13 事故**：源码还停在 375/1.40/8 声部，烧进去又 USB 失败；已回 300/6。
- **全浮点 VCO**：相位从 uint32 改为 float，查表插值改为 float（`y0+(y1-y0)*frac`），去掉 uint32/int32 定点插值；表数据仍是 int16，但读取后立即转 float。
- **ADSR 范围**：D/R 从 1ms..10s 扩到 **0.5ms..20s**；D/R 仍是“实际时长”指数（到 ~1%）。
- **滤波系数优化**：`g`/`a1`/`b1` 每 16 采样更新一次（仍用 float），减少每采样除法；6 声部 300MHz core1 约 82%（优化前 88.6%）。
- **FPU**：滤波、ADSR、VCO 全是 float；FPU 已用。定点只剩 ADC/DAC 硬件和表数据。
- **当前 v15**：300MHz/6 声部，COM21 正常；6 声部 core1≈82%，释放≈67%，空闲≈5%。
- 采样率仍 48k（96k 在 6 声部下 CPU 不够）。
- 产物：`pico_jp8000_20261019_v15.uf2`；`pico_jp8000_v11.ino.bak`。

### 11) JP-8000 电路资料结论（2026-10-19 查服务手册）
- 服务手册 31 页（`参考资料\Roland-JP-8000-Service-Notes.pdf`）是扫描件；主电路图页 19 明确画出 **DSP_BLOCK / DSP_SC / DAC_BLOCK**：
  - 声音合成（VCO / VCF / 两个 ADSR）在 **Roland 定制 DSP 内部**，是数字算法；板上没有 VCO/VCF 的分立晶体管/OTA/电容网络。
  - 板上模拟部分只有：DAC（L/R）、I/V 与输出低通/静音、电源、键盘扫描、面板 ADC。
- JP-8000 是 **16-bit 数字虚拟模拟合成器**（Wikipedia/服务手册），不是像 TB-303 那样的全模拟电路。
- **结论**：无法像 303 那样“按电路图取原件值做 SPICE”来复刻 VCF/ADSR；原始 VCF/ADSR 没有可仿真的分立元件。能做的只有：
  1. **行为级 DSP 模型**（现在的 SuperSaw + SVF + ADSR），用 JP-8000 录音/插件做参考拟合；
  2. 用服务手册 **模拟它的模拟输出级**（DAC I/V + LPF + muting），再接我们的 DSP；
  3. 若坚持“电路级”，只能仿一个 **Jupiter/OTA 梯形滤波器** 作为风格模型，但它不是 JP-8000 原电路。
- 后续若要真正贴近 JP-8000：需要 **JP-8000 的滤波扫频/包络录音**（或 Arturia Jup-8000 V / Super Hahmo 等插件）做 A/B，拟合共振映射和 ADSR 曲线。

### 12) v16：双极 Filter Env Depth + -60dB 包络
- `pEnvDepth` 改为 **-1..+1**（ACCENT 中心=0，左负右正），滤波包络可反向；深度 ±6 oct。
- D/R 指数系数从“到 1%”改为 **到 -60dB**（`exp(-6.907755/(T*SR))`），更接近 Spire/Serum 的“时间=听感衰减时间”。
- v16 已烧录，300/6，COM21 正常；T 可看到 amp/filt 两套 D/S/R。
- 下一步：若 ADSR 仍觉得不对，优先补 **小屏显示当前 ADSR 值**，避免物理旋钮 pickup 造成误判。

### 13) v20/v21：小屏 PIO + 看门狗自动恢复 + 375MHz 的真正根因（QMI/XIP 分频）
- **小屏**：第一版硬件 SPI 全屏推送卡死 loop（逐字节 transfer）→ 改为 OV-03 同款 **PIO + DMA** 推屏；`fb` 115KB，60fps 级别的 DMA 由 PIO 时钟 `clk_sys/4N` 推。
- **看门狗自动恢复**：`watchdog_hw->scratch[0]` 存 `"JP80"+bootCount`；开机计数，setup 完整跑通清 0；看门狗 4s。连续 2 次没跑完 setup → **自动 `reset_usb_boot`**（不再需要手动按 BOOT）。
- **★ 375MHz 根因（用户提醒正确）**：不是电压，是 **flash QMI/XIP 读分频**。升主频前必须：
  ```c
  cd = ceil(CPU_KHZ / 100MHz);
  qmi_hw->m[0].timing = (qmi_hw->m[0].timing & ~0xFF) | cd;
  dummy XIP read;
  set_sys_clock_khz(...);
  ```
  OV-03 里早就有这段，新固件漏了。补上后 **375MHz USB 正常枚举**。
- **v21 当前**：375MHz @1.30V，**8 声部**，PIO 小屏，watchdog 自动恢复。
  - 8 音和弦实测：RMS≈-19/-17dBFS，peak≈-5.5/-3.8dB，L/R corr≈0.65；8 声部 core1≈86%，空闲≈4.5%。
  - 屏幕显示 8 旋钮：CUT/RES/D/S/R/DEP/DET/MIX，D/S/R 随 SW1 的 AMP/FILTER 编辑目标显示 `-AMP`/`-FIL`。
- **产物**：`pico_jp8000_20261019_v21_375_pio.uf2`；屏幕驱动 `lcd_spi.pio.h` + `font5x7.h` 已放入 `pico_jp8000\`。
- **备注**：375/8 下 core1 86% 偏高，若现场有爆音/卡顿，优先降到 6 声部或 300MHz；QMI 分频逻辑保留。

### 14) v22：滤波器高共振限幅/可自激
- `gK = 2.0 - 2.02*res`（res=1 时轻微负阻尼 → 可自激），`satState()` 只在高电平（|v1|>0.95）限幅，正常信号不压缩。
- 12dB 和 24dB 第一级都走 `satState`；高共振不再无限增长，同时保留 JP-8000“高共振可振荡”的行为。
- 375MHz/8 声部：8 音和弦 RMS≈-19/-17dBFS、peak≈-5.3/-3.9dB，core1≈89%；res=1/cut=300 实测输出集中在基频附近、无爆炸/削顶。
- 产物：`pico_jp8000_20261019_v22_selfosc.uf2`；当前板子已烧 v22（375MHz/8 声部/PIO 屏/watchdog）。

### 15) v24~v26：解决“bitcrush”感
- **根因 1：8 声部 CPU 太高（89%）** → I2S 偶发欠载/丢样本，听感像 bitcrush。
  - v24 把每声部 7 个锯齿的 **频率增量、左右 pan、mix 增益** 放到“每块预计算”，采样内只做 `ph += inc` + 查表 + 乘加；
  - 375MHz/8 声部 core1 从 **89% → 55.6%**，释放 ≈39%，空闲 ≈4%。
- **根因 2：小 mip 表 + 线性插值** → 高音/复音时有插值镜像（也像 bitcrush）。
  - v26 把 mipmap **最小表长从 8 提到 512 点**（`SS_TAB_POOL_PTS 60000→86000`，RAM 77%），继续用线性插值（CPU 低）；高音 n84 实测谐波 1046/2093/3139/4186/6281… 全是整数倍，无明显非谐波镜像。
- **v25 试过三次插值**：音质好但 8 声部 core1 回到 88%，不划算；已回退线性 + 512 点表。
- **当前 v26**：375MHz/8 声部，PIO 小屏，watchdog，QMI 分频；8 声部 core1≈55.6%。
- 采样率仍是 **48k**（I2S 实际没掉；之前是 CPU 欠载 + 小表插值，不是 DAC 采样率）。
- 产物：`pico_jp8000_20261019_v26_bigtable.uf2`；当前板子已烧 v26。

### 16) v27/v28：小屏不阻塞 + 撤销滤波内部饱和（bitcrush 最后一刀）
- **小屏卡死/旋钮无反应根因**：`lcdPushAll()` 在 loop 里**阻塞等 DMA**；DMA/PIO 一旦卡住，core0 卡死 → 屏幕不动、旋钮不读。
  - v27 改为 **非阻塞**：`lcdPushAll()` 只启动 DMA 返回；`lcdTask()` 在 loop 里收尾；DMA 超过 300ms 自动 abort/reset PIO；刷新降到 500ms。
  - 现在 core0 不再被屏幕拖死，旋钮/串口正常。
- **bitcrush 根因 3：滤波内部 `satState` 限幅**：8 声部低频叠加后，SVF 的 bandpass 状态经常 >0.95，被 `satState` 削波 → 低频 bitcrush 味。
  - v28 **撤销 `satState`**（恒等），`gK` 恢复 `2.0 - 1.95*res`（最小 0.1，不再负阻尼/自激）。
  - 保留输出端 `fastTanh` 软限幅。
- **当前 v28**：375MHz/8 声部，PIO 非阻塞小屏（2fps），QMI 分频，watchdog；8 声部 core1≈55%。
- 产物：`pico_jp8000_20261019_v28_cleanfilter.uf2`；当前板子已烧 v28。
- **若还有 bitcrush**：用串口 `L0` 停屏、`l1` 切 12dB、或 6 声部逐项隔离；低频重点听 24dB/滤波输入电平。
### 17) v29：小屏 24Hz 局部刷新
- 全屏 115KB 每帧推在 24Hz 会吃总线；改为 **4 个 60 行带**，只推有变化的带（`lcdBandMask`）。
- 每个旋钮单元 120x60；只有值/文字变化才重画该单元并置对应行带；D/S/R 在 SW1 切目标时整组重画。
- 刷新率 **24Hz（41ms）**；`lcdTask()` 非阻塞，DMA 一次推 60 行（≈4.9ms），core0 空闲。
- 8 声部/375MHz：core1≈54%，屏幕 24Hz 局部刷新；当前产物 `pico_jp8000_20261019_v29_lcd24.uf2`。
### 18) v30：修小屏“旧指针线不消失/到极值消失”
- **根因**：`lcdPushBand()` 的 DMA 传输字数写成了 `60*240/4`，只推了 **30 行**（一个 60 行带的一半）。
  - 指针在单元下半部时新线没推上去 → 看着像“线消失”；旧线在上半部没被覆盖 → “旧线留在原地”。
- **修复**：改为 `60*240/2`（32bit 字 = 2 像素；60 行 = 7200 字），整带 60 行完整覆盖。
- 产物：`pico_jp8000_20261019_v30_bandfix.uf2`；当前板子已烧 v30。

### 19) v31~v34：低频 bitcrush 根因定位 + A/B ADSR + HPF 修正
- **v31/v32 诊断固件**：串口新增 `S1/S0` 1kHz 纯正弦直出、`B1/B0` VCF 旁路、`N1/N0` 输出限幅开关、`O<0..2>` 主增益、`H1/H0` HPF 旁路、`C1/C0` 滤波系数每采样/每16采样、`L0/L1` 停/开屏、`Q` CPU 统计。
- **实测结论**：
  - 1kHz 纯正弦直出：THD 约 -50dB，I2S/DAC/屏 DMA 没有数字毛刺；`L1` 屏开与 `L0` 屏关无差异。
  - VCF 旁路/正常、限幅开/关（同增益、单音 C2）没有出现量化/丢样；`fastTanh` 只在很高电平产生少量谐波，不是低频 bitcrush 主因。
  - **真正根因：每声部 HPF 截止频率 = f0（OV-303 遗留）**。C2 单音实测：HPF 在 f0 时基波被 2 阶高通削掉约 3.8dB，40–80Hz 能量占比 36.5%；HPF 旁路后 RMS -21.6→-17.8dBFS，40–80Hz 占比→63.9%。低频因此发薄、发炸，听感像“碎”。
  - **修正**：`hpA` 改为固定 20Hz 次声高通（voiceOn 和每块更新两处），不再跟随 f0。修正后 C2 RMS -18.4dBFS，40–80Hz 占比 60.7%。
- **ADSR**：
  - v33 曾试过 AMP/FILTER 路由（AMP 模式 VCF 静态；FILTER 模式 VCA 固定 gate），实测可用但 FILTER 模式会丢掉 AMP 包络，不符合“两套切换”的本意。
  - **v34 改为 A/B 两套 ADSR**：SW1 选择当前生效的一套（低=A，高=B）；当前套同时控制 VCA 和 VCF 深度（DEP 旋钮仍为滤波包络量）；A/B 的 D/S/R 分别保存，屏幕显示 `D-A/S-A/R-A` 或 `D-B/S-B/R-B`，`T` 打印 `A/B d/s/r + active`。
  - 单音实测：A（D0.6/S0.5/R0.5）RMS -20.7→-24.8dBFS、频谱质心 353→255Hz；B（D0.1/S0.2/R0.3）RMS -25→-33dBFS、质心 265→188Hz；离键释放正常。
- **CPU**：375MHz、8 声部、屏开，core1 约 **57.1%**（`Q` 稳定值）；仍有余量。
- **文件**：`pico_jp8000_20261019_v34_ab_adsr.uf2` 已烧录；源码 `pico_jp8000\pico_jp8000.ino`。
- **诊断串口**：`?` 看命令；`S1` 正弦、`B1` VCF 旁路、`H1` HPF 旁路、`N0` 关限幅、`O0.25` 降主增益、`C1` 滤波系数每采样、`L0` 停屏、`Q` CPU。

### 20) v35：ADSR 改为 Vital 位置式，release 时间精确
- **参考 Vital `envelope.cpp` 的逻辑**：
  - 每个阶段有自己的 `position` 0→1，`delta = 1 / (time * sample_rate)`；到 1 就切下一阶段。
  - release 用 `start_value * (1 - powerScale(position, release_power))`，`start_value` 是 noteOff 时的当前电平；所以 **release 时间 = 从 noteOff 到 0 的固定时间**，不随 sustain 高低改变。
  - noteOn 时 `start_value = 当前 value`，attack 从当前电平开始，不强制归零。
- **旧实现的问题**：`level *= exp(-6.907755/(T*sr))` 是“相对当前电平衰减到 -60dB”的指数曲线，再用 `0.0005` 截断。低 sustain 时实际尾音明显短于设定值，高 sustain 时又拖得很长；retrigger 还会从 0 重新 attack，容易 click。
- **v35 新实现**：
  - `ADSR` 增加 `pos`、`start`；attack/decay/release 全部按 `pos` 0→1 推进。
  - `calcAdsrCoefs`：`atk/dec/rel = 1/(time*sr)`，decay 是到 sustain 的准确时间，release 是到 0 的准确时间。
  - 曲线用 `envShape(p)=1-(1-p)^2` 近似 Vital 的 `powerScale`：release = `start*(1-pos)^2`，衰减快、尾部自然，且 pos=1 精确归零。
  - `noteOn` 从当前 level 开始 attack；retrigger 不再跳回 0。
- **实测（单音 C4，decay 0.2s，sustain 0.2）**：
  - release 0.5s：-40dB 约 0.45s；release 1.0s：约 0.9s；release 2.0s：约 1.8s（按二次曲线理论值）。
  - sustain 0.2 与 sustain 0.8，在 release=1.0s 时都是约 1s 到 0，不再随 sustain 改变。
- **文件**：`pico_jp8000_20261019_v35_vital_adsr.uf2` 已烧录；源码 `pico_jp8000\pico_jp8000.ino`。
- **下一步**：用户试听 release；如果希望更接近 Vital 的 `powerScale` 曲线（可调曲线），下一步可把 `release_power` 做成固定值/隐藏参数，或加一个曲线表。

### 21) v36：完全对标 Vital 默认包络曲线
- 从 Vital `synth_parameters.cpp` 确认默认值：
  - `attack_power = 0.0`（attack 线性）
  - `decay_power = -2.0`
  - `release_power = -2.0`
  - `powerScale(p, power) = (exp(power*p) - 1) / (exp(power) - 1)`。
- v35 用的是二次曲线近似；v36 改为 **Vital 原始 powerScale**：
  - 预计算 512 点 `power=-2` 曲线表 `envCurve[]`，运行时线性插值，避免每采样 `expf`。
  - attack：`start + (1-start)*pos`（power=0）。
  - decay：`1 - (1-sus)*powerScale(pos)`。
  - release：`start*(1 - powerScale(pos))`，`pos` 仍按 `1/(release*sr)` 推进。
- **实测（单音 C4，sustain 0.5，release 1.0s，k=0）**：
  - release 0.4s 处约 -8.7dB（相对起音），理论 power=-2 为 -8.8dB；0.8s 处约 -25dB，1.0s 到噪声底。
  - retrigger：noteOff 后 0.5s 再 noteOn，从当前电平 attack 到 1，没有跳回 0；第二次 release 正常。
- **CPU**：375MHz/8 声部/屏开，core1 **56.5%**。
- **文件**：`pico_jp8000_20261019_v36_vital_exact.uf2` 已烧录；源码 `pico_jp8000\pico_jp8000.ino`。
- 说明：目前 UI 没有暴露 power 旋钮；固定使用 Vital 默认值。若要像 Vital 一样可拖动曲线，可下一步加一个全局 `curve` 参数并重建曲线表。

### 22) v37：恢复 AMP/FILTER 双 ADSR 同时生效，切换不再重置旋钮
- **用户反馈**：SW1 切换像“换了两套滤波器”；D/S/R 旋钮切换后会重置；实际上应该是一套 AMP ADSR、一套 FILTER ADSR，两者同时控制，不是二选一。
- **v37 修正**：
  - 恢复双 ADSR：`v.amp` 每采样运行 AMP ADSR → VCA；`v.filt` 每采样运行 FILTER ADSR → VCF cutoff。两套都生效。
  - SW1 只切换“旋钮编辑/屏幕显示”的对象（低=AMP，高=FILTER），不再切换生效的包络。
  - 屏幕恢复 `D-AMP/S-AMP/R-AMP` 与 `D-FIL/S-FIL/R-FIL`；`T` 同时打印两套 D/S/R 和 `edit=AMP/FILTER`。
- **旋钮不再重置**：
  - 删掉切换时的 `resetPickup()`。
  - 改为**相对编辑**：`envNorm[2][3]` 保存 AMP/FILTER 两套归一化 D/S/R；开机时两套都从当前电位器初始化（这就是“刚开机重置”），之后切换只改变编辑对象，转动旋钮是在当前套的已保存值上做增量，不会跳变/覆盖另一套。
  - 切换 `e0/e1` 实测两套 D/S/R 数值保持不变。
- **Release**：
  - 两套包络各自使用 Vital 位置式 + `powerScale(power=-2)`；AMP release 只影响 VCA，FILTER release 只影响 cutoff，二者不再互相绑定。
  - 单音实测：AMP 释放时 VCA 按设定时间下降；FILTER 释放时频谱质心独立下降，互不覆盖。
- **CPU**：375MHz/8 声部/屏开 **58.0%**。
- **文件**：`pico_jp8000_20261019_v37_dual_env.uf2` 已烧录；源码 `pico_jp8000\pico_jp8000.ino`。
- **注意**：现在 SW1 是“编辑对象”，不是“生效对象”；两套包络始终都在跑。若希望某一套暂时旁路，需要另加开关/参数，而不是复用 SW1。
